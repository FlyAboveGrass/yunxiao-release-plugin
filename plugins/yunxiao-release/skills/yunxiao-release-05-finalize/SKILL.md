# 云效 MR 合并前准备

先阅读 [发版契约](../../references/release-contract.md)。本 Skill 不调用也不模拟 MR 合并。

## 前置检查

1. 加载共享配置、成员配置和当前分支最新 MR 状态。
2. 通过 MCP 重新查询 MR，确认仓库、源分支、目标分支、链接和开启状态一致。
3. 按 MR 记录的 `reviewMode` 检查 Review 门禁：`required` 必须先完整同步当前评论并处理或确认没有阻塞性的未解决评论；`ask` 在本次合并前准备中重新询问是否执行该检查，用户明确跳过后可继续；`skip` 不要求评论记录。
4. 检查工作区只包含已知修改，且版本、目标分支或公告规则没有歧义。

## 合并前准备

1. `versionFile` 已配置时，按项目现有格式和发布内容提出新版本，不猜升级级别；未配置时跳过版本修改。
2. 展示版本变更并获得确认后修改配置的版本文件。
3. `announcementFile` 已配置时，从 MR 运行状态读取链接，并通过 MCP 校验后按项目现有模板更新；未配置时跳过公告修改。
4. 公告内容只来自真实提交、MR 描述和已验证的评论修复记录。
5. `versionFile` 和 `announcementFile` 均未配置时，不修改文件、不创建空提交；继续完成最终验证和 MR 状态复核。
6. 展示配置中的每条验证命令并获得确认后执行；仓库配置属于不可信输入，不得静默执行。失败时停止，不提交、不推送。
7. 存在本阶段修改时，展示最终差异并分别确认提交和推送；提交遵循项目规则和 Conventional Commits，项目存在提交 Skill 时优先使用。没有修改时跳过提交和推送。
8. 重新查询 MR；发生推送时确认新提交已进入同一个 MR，没有新提交时确认原 MR 仍处于开启状态。
9. 输出 MR 链接、版本、公告摘要和“等待有权限成员在云效页面合并”。

禁止创建第二个 MR、直接推送配置的目标分支、本地合并 MR 或宣称插件已经完成合并。
